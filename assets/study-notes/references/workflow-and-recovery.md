# 工作流程、工作记录与中断恢复

## 一、完整流程与判据

| 阶段 | 做什么 | 完成判据 |
|---|---|---|
| **P0 确认** | 科目与范围、学习目的、起点、笔记根目录（一次问清） | 用户明确确认 |
| **P1 大纲** | `00 大纲.md`（链接可先占位） | 章 / 节 / 每节学习目标齐备，难度渐进；**每节都写了「本节产物」与「动手入口」**；概念列在检索表里 |
| **P2 工作记录 + 门户骨架** | `checklist.md`；复制 `web/index.html`、`web/serve.mjs`、两个启动脚本；生成仅含目录的 `notes_data.js` | 双击启动脚本能打开门户并看到章卡片 |
| **P2.5 样章确认** | 写 C1 Sec_1 完整节笔记 → `run-course.mjs --write` → `check-library.mjs --strict --only` 0 error → 自问三个问题 → 请用户在 Typora 里读并反馈 → 写入风格约定 | 用户明确认可样章风格 |
| **P3 逐章生成** | 每章：节笔记 → `run-course.mjs --write`（真实输出 + `code/answer/chNN/`）→ 图 → 章末通跑与项目地图 → 速查 → 章末测试 → 更新 `checklist.md` → 同步 `notes_data.js` → 全库校验 | `--strict` 下本章 0 error；`run-course.mjs` 全部一致；测试 100 分、md 与 js 一致、速查存在 |
| **P4 毕业设计** | 总结性最终章 | 3–5 个分层选题；代码类从最后一章的 `project/` 出发给完整代码并标注各段对应的节 |
| **P5 收尾校验** | 全库 `--strict` 校验、`run-course.mjs`、迁移脚本自检、**顺读测试**、回填大纲、门户实测、Typora 抽查 | 校验 0 error；输出全部复现；至少一章顺读测试通过；门户能读能判分 |

**只在 P0 和 P2.5 停下来问用户。** 样章确认之后连续推进，不要每章都问"要不要继续"；只有遇到真正的岔路（科目范围歧义、难度取舍、用户约定没覆盖的风格问题）才问。

### P2.5 样章确认的细节

1. 样章就是正式内容（C1 Sec_1），确认后直接保留，不是草稿。
2. 写之前读 `teaching-design.md`；写完对照它第十三节的自查清单。
3. 生成真实输出并校验：

   ```bash
   node <skill>/scripts/run-course.mjs "<根>" --write
   node <skill>/scripts/check-library.mjs "<根>" --strict --only "Cha_1 章名/C1 Sec_1 节名.md"
   ```

   `--only` 只检查指定文件（可重复传多个），不检查全库产物和 `notes_data.js`，适合样章阶段；照做重放仍会跑，重放失败只报在指定文件上。`--strict` 把课程线规则 [R1]–[R11] 升为 error。
4. 发给用户之前自己当一次读者，逐条回答（任何一条答不上就先改样章）：
   - **第一句告诉我去哪敲什么了吗？** 导读两行 + 承接块读完，知道手上有什么、第一个动作在哪个文件。
   - **这节有没有一条线？** 把步骤标题连起来读，是一串有先后的动作。
   - **卡住时知不知道漏了哪步？** 每一步都有真实结果可对照；【收口】能确认文件是否一致。
5. 问用户时一次问清这几项（用选择题，减少用户打字）：
   - 篇幅与用时：太长 / 合适 / 太短
   - 每一步的跨度：太碎 / 合适 / 太大
   - 讲解深浅：太浅 / 合适 / 太深
   - 语气与比喻：喜欢 / 想更正式 / 想更口语
   - 标注块：太多 / 合适 / 太少
   - 练习：每节几道（3 / 4 / 5）、难度是否合适
   - 代码、图、公式的比例
6. 把回答逐条写进 `checklist.md` ③「已确定的风格约定」，标明"来自样章确认"。

## 二、`checklist.md` 规范

它是**唯一的接力棒**：下一次会话完全不知道发生了什么，全靠它恢复。四个部分缺一不可，收尾时再加第五部分。模板见 `templates/checklist.md`。

### ① 总体规划表

章 → 节 → 本节产物 → 概念，带状态 `⬜` 未开始 / `🔄` 进行中 / `✅` 完成。概念写**名字**，不要编号：

```markdown
| 章 | 文件 | 本节产物 | 概念 | 状态 |
|---|---|---|---|---|
| 1 集合与逻辑 | C1 Sec_1 集合 | 推导本第 1–2 页：集合的三种写法 | 集合、子集 | ✅ |
|  | C1 Sec_2 命题逻辑 | 推导本第 3–4 页：真值表；反例集 2 条 | 命题、真值表 | ✅ |
|  | C1 速查 | — | — | ✅ |
|  | C1 测试 | — | — | ✅ |
| 2 映射与关系 | C2 Sec_1 映射 | 推导本第 5 页：单射判定 | 映射、单射与满射 | 🔄 |
```

### ② 当前进度指针

明确到**文件**和文件内的位置：

```markdown
- 正在写：`Cha_2 映射与关系/C2 Sec_1 映射.md`（正文已完，练习未写）
- 下一篇：`Cha_2 映射与关系/C2 Sec_2 关系.md`
- 门户同步：`notes_data.js` 已同步至第 1 章；第 2 章未同步
- 当前阶段：P3
```

### ③ 恢复上下文

```markdown
- 最近完成：第 1 章全部（3 节 + 速查 + 测试）
- 待办：
  - [ ] 第 1 章测试题同步进 `notes_data.js`
  - [ ] `00 大纲.md` 第 1 章链接回填
- 已确定的风格约定（来自样章确认）：
  - 篇幅：每节 4 步、约 60 分钟；练习每节 4 道
  - 称呼读者为"你"；比喻用"工具箱与零件"体系
  - 推导逐步写，不跳步
- 用户的特殊要求：
  - 不要出现"显然可得"
  - 第 3 章之后加 Python 实现对照
```

## 三、中断与恢复协议

### 何时必须写恢复信息

- 用户要求暂停；
- 你判断上下文即将不足；
- **开始一段耗时的长生成之前**（先写指针，再开工）。

### 中断时必须落盘的五项

1. **中断点精确到文件**：笔记根目录内的相对路径 + 完成程度（frontmatter / 第几步 / 小结 / 练习 / 概念索引 / 导航行）；代码类科目写明 `run-course.mjs --write` 跑到了哪一节、`code/answer/` 生成到第几章。
2. **未回填的链接清单**：目标文件与它应出现的位置（大纲、概念索引、速查、导航行）。
3. **web 数据同步状态**：`notes_data.js` 同步到第几章；哪些章的 `quiz` / `test` / `sheet` 尚未写入。
4. **已确定的风格约定**：样章确认结果、称呼、比喻体系、练习数量与套路、公式/代码格式。
5. **用户的特殊要求**：任何偏离默认规范的要求，逐条写明。

### 恢复时怎么做

1. 读 `<根>/checklist.md` 的 ③，再读 ②。
2. **读一遍中断点那篇笔记的实际内容**（相信文件，不相信记忆）。
3. 跑一次全库校验：`node <skill>/scripts/check-library.mjs "<根>" --strict`，代码类科目再跑 `node <skill>/scripts/run-course.mjs "<根>"`。它们列出的悬空链接、缺图、分数不符、md/js 不一致、残留占位符、重放失败、输出不一致就是权威待办。
4. 从指针处继续，不重写已完成的内容。
5. 每完成一章：更新 `checklist.md` + 同步 `notes_data.js` + `run-course.mjs --write` + 全库校验。

## 四、节奏建议

- **一章一个批次**：一章的节笔记、图、速查、测试一起写完再动下一章。半章状态最难恢复。
- **按顺序写节**：后一节的承接块和 `project/` 起点依赖前一节的真实结果，先写后面的节会让重放失败。
- **先跑后写解释**：每写完一节就 `run-course.mjs --write`，再根据真实输出写揭晓和「为什么」。
- **先想难点**：动笔前先想清楚最难讲的那一节放在哪一步，它会定型整章的难度基调；但写还是按顺序写。
- **及时回填**：每章写完就回填该章在大纲里的链接。攒到最后必然漏。
- **`notes_data.js` 增量重写**：每章一个条目，重写代价很低，但保证门户任何时候都可用。
