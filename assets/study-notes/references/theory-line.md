# 理论线：概念与论证型科目怎么教

这篇是 `SKILL.md` 铁律与 R1–R13 之外的**第二条线**。实践线（编程、算法、带脚本的自然科学）教的是"读者从空目录长出一个能跑的东西"；理论线（纯理论、人文社科、语言、应试、操作型里的概念部分）教的是"读者手里长出一份能自己复述、能拿来判对错的知识卷轴"。

**先判断用哪条线**，再动笔：

| 核心能力 | 用哪条线 | 典型科目 |
|---|---|---|
| 构造 / 调试出一个能跑的东西 | 实践线（R1–R13） | 编程、软件工程、算法、带脚本的实验课 |
| 推导 / 论证 / 辨析 / 复述 | 理论线（L1–L8） | 数学、理论物理、哲学、历史、法律、经济、语言学、纯概念课 |
| 一半推导一半动手 | 混合：**按章**分配两条线 | 计量经济、计算物理、机器学习理论课 |

判断方法：问"读者学完这一节，手里该多出一样**能拿给别人看**的东西吗？"能拿出来的是一段能跑的程序 → 实践线；是一页推导、一条时间线、一张对照表、一段能背下来的复述 → 理论线。

---

## 一、两条线的分工

| 维度 | 实践线 | 理论线 |
|---|---|---|
| 每节产物 | `project/` 里多出或改动的文件 | 知识卷轴上多出的一截：概念地图、时间线、推导稿、对照表 |
| 步骤里的"做" | 【新建】/【修改】/【重构】/【运行】 | `<b>动手</b>：…`（手算一次、画一张表、合书复述一遍） |
| 每步的"看" | 绑定的真实输出 | `<b>你应该看到</b>：…`（读者自己写出来的那一行式子 / 那张表 / 那段复述） |
| 章末通跑 | 一条命令跑完整个 `project/` | 合上书，把本章的概念地图与时间线复述一遍 + 限时自测 |
| 章末项目地图 | 文件树 | 知识卷轴的目录（推导本第几页、时间线新增哪几段） |
| 校验 | `check-library.mjs` 的 R1–R13 | 同样过 `check-library.mjs`（格式），外加本篇 L1–L8（人工） |
| 节骨架模板 | `templates/section-note.md` | `templates/section-note-theory.md` |

两条线共用同一套节骨架与讲解四拍（想 → 讲 → 做 → 看）。**不要**给理论课硬套 `project/`，也不要为了"像代码课"而在理论节里零散塞代码片段。

---

## 二、规则 L1–L8

这八条是理论线的纪律。**校验器不检查**（`check-library.mjs` 只兜格式与 R1–R13），所以更要自己守住；交付前按 `quality-gates.md` 人工过一遍。

| 编号 | 规则 |
|---|---|
| L1 | **四拍不变，"做"降级为轻动手**：每一步仍是 先想 → 讲 → 做 → 看；"做"是读者 30 分钟内能独自完成的一次小动作——手算一个例子、画一张对照表、合书复述一遍、给一个说法找反例。<b>动手</b>：… 与 <b>你应该看到</b>：… 必须成对出现，读者要能自己判断做对没有 |
| L2 | **产物是知识卷轴**：每节的产物写进导读的 <b>本节结束时</b>，必须是 累积（上一节的基础上加）、可检验（自己能判对错）、可修改（后面的节会回头改）。卷轴由三样东西组成，按科目取用：<b>概念地图</b>（概念之间的依赖与对比）、<b>时间线</b>（历史/流派/事件）、<b>推导或论证稿</b>（一步步的式子或论点链） |
| L3 | **讲解是绝对主体**：T1（先讲后做 ≥8 行）、T2（概念 40–120 行）、T5（讲解不少于代码）照用；理论线没有代码可对冲，正文（不含表格与代码）应占本节篇幅的 60% 以上。宁可少讲一个概念，也不要把概念写成名词解释清单 |
| L4 | **每章至少一张结构图**：概念图、时间线、学派对照表、论证结构图——四选一以上，用 Mermaid（`flowchart` / `timeline` / `mindmap`）或 Markdown 表格。图要**承载关系**（谁依赖谁、谁先谁后、谁反对谁），不是装饰 |
| L5 | **引用只标硬事实**：只有四类内容必须行内标注来源——① 具体数字（统计量、实验值、年代跨度）② 具体时间点/版本 ③ SOTA、"最/首次/唯一"这类断言 ④ 机构、人物、学派的归属。其余论断不逐句加注；每章最后一节末尾用 `### 来源与时效` 汇总本章引用了什么、哪些结论可能过时。**不确定就不引**，宁可写「此处存疑，待核实」，绝不编造出处 |
| L6 | **章末通跑 = 合书复述**：本章最后一节的最后一步标题写「章末通跑」，内容是让读者**合上笔记**复述本章概念地图（口述或默写），再用 `<b>你应该看到</b>：…` 给出对照表；紧接着 `### 本章项目地图` 换成知识卷轴的目录。此处不许再"读一遍"充数——读一遍不算通过 |
| L7 | **练习按三类出**：1 题**辨析**（两个易混说法，判断哪个对、那个错的错在哪）、1 题**复述**（用自己的话解释某个概念或推导关键一步）、1 题**应用**（给一个新材料/新情境，用本节工具判断）。第 4、5 题出综合（串起本节多个概念）或跨章回顾 |
| L8 | **局部代码课与 notebook**：某个小节确实需要跑代码（数值验算、可视化、小实验）时，**整节或整步**改成实践线写法（R1–R13 照用），不要一句话塞一段代码。notebook 放 `code/notebooks/CN_主题.ipynb`，是读者的实践场：一格一件事、随手跑、可放小实验与可视化，交付时不带输出（读者自己跑），正文不依赖它的结果 |

## 三、理论线的节骨架

与 `templates/section-note.md` 同构，只有四处不同（模板见 `templates/section-note-theory.md`）：

1. **导读三行照旧**：<b>你现在手上</b>（卷轴上已有什么）/ <b>本节结束时</b>（多了哪一截）/ <b>本节要回答</b>（一两个真问题）。预计用时仍写 30–100 分钟，3–5 步 × 10–20 分钟。
2. **`## 接上一节` 三行照旧**：上一节做到 / 留下的坑 / 本节补上。理论课的"坑"通常是"上一节的解释还解释不了的现象"。
3. **每一步的四拍**：
   - **想**：`> <b>*Tip*</b>` + 先想一下/先猜一猜，让读者先给出自己的说法；
   - **讲**：≥8 行，通常 20–60 行，讲清问题、原理、推导或论证（数学不跳步，人文要并列不同立场）；
   - **做**：`<b>动手</b>：在推导本 / 时间线 / 对照表上写下……`——一次 30 分钟内能做完的动作；
   - **看**：`<b>你应该看到</b>：……` 给出读者应得的结果，再接 `<b>刚才发生了什么</b>` 或 `<b>为什么是这个结果</b>` 把结果对回讲解。
4. **章末两件事改成三件**：章末通跑（合书复述 + 自测）、本章项目地图（知识卷轴目录）、`### 来源与时效`（仅本章最后一节，放在 `## 概念索引` 之后）。

概念写法与 `### 概念 N：名称` 的编号规则**完全照旧**（门户徽标靠编号定位）；每节 3–5 道练习、每章 100 分测试、速查、门户同步这些硬要求也照旧。

## 四、引用怎么写

只在四类硬事实后面加来源，写在句末括号里，不写脚注编号、不写学术引用格式：

```markdown
2023 年这项任务的 SOTA 是 87.4%（来源：XX 实验室 2023 年度报告，2024-03 更新）。
```

- 来源写到"哪个机构/哪个版本的哪份材料 + 什么时候"，读者能自己找回去即可；
- 同一个来源在一节里出现两次以上，第二次写"同上"；
- 章末 `### 来源与时效` 用列表汇总：本节引用了什么、哪些结论依赖某个会变的数字、读者应该去哪里核实最新值；
- **时效**是理论线特有的一栏：凡是会随版本/政策/研究进展变化的结论，都要在这里点名，不要在正文里假装它是永久真理。

---

## 五、与实践线混合

混合库（一半推导一半动手）**按章分配**，不要在一节里混两套骨架：

1. 在 `00 大纲.md` 的章表里给每章标 `类型：理论 / 实践`；
2. 每章内部只用一种节骨架模板；
3. 章与章之间的衔接在 `## 接上一节` 里写清"上一章的理论现在要拿来动手"或"上一章跑出来的现象现在要解释"；
4. 大纲的"本节产物"列按类型分别写（理论章写卷轴产物，实践章写 `project/` 变化）。

---

## 六、停点建议

理论线的天然停点是**一章的卷轴成形时**（概念地图 + 时间线更新完、章末复述做完），不是某一节写完时。逐章停模式下按章交付；不要在节中间停下来问"要不要继续"。

交付时对读者说三件事：这一章卷轴多了哪一截、自测结果如何、哪里最可能不合他的口味（讲深了 / 讲快了 / 例子不好）。**每个项目只在第一章交付后**主动给一份"你可以改的地方"清单，后面各章等他自己说。
