# 质量红线与交付前自检

交付前的最后一道关。**逐项过，不允许"大概没问题"。**

---

## 一、内容红线（最重要）

> 如果你对某个科目或某个内容实在不理解，并且联网搜索也不能解决，**不要随意生成**。
> 你的教学内容将完全被用于用户的学习，**错误的内容是无法容许的**。

| 项 | 要求 |
|---|---|
| 知识 | 定义、定理、分类、术语准确；不确定就搜、就问、就标注存疑 |
| 代码 | 逻辑正确；**读者能照做敲出来、不是节选**：每个代码块带【新建】/【修改】/【重构】/【收口】标签和 `project/` 路径，从空目录照正文做下来能跑；不露出后面章节的版本；伪代码标 `text` |
| 输出 | 只写真实运行结果，并用 `<!-- output: -->` 绑定；由 `run-course.mjs` 在照做重放的快照里跑出来；没跑过就不要写"输出"；不含本机绝对路径 |
| 公式 | 推导逐步可查，不跳步；符号先定义后使用；每个等式都有成立条件 |
| 案例 | 数据自洽；算例的每个中间量都能对上 |
| 引用 | 只引用确实知道出处的来源；不编造书名、页码、链接 |

**"标注存疑"的写法**：

```markdown
> <b>*Warning*</b>
> 此处存疑
>
> 关于 $X$ 的取值上限，不同教材有 $n-1$ 与 $n$ 两种约定。本笔记采用 $n-1$（与正文例题一致）。
> 若你的考试用书不同，请以考纲为准。
```

宁可有标注的空白，不要有自信的错误。

## 二、工程红线（脚本可查）

新库跑 `node <skill>/scripts/check-library.mjs "<根>" --strict`，代码类科目再跑 `node <skill>/scripts/run-course.mjs "<根>"`，下列每一项都必须无 error：

- [ ] 命名符合 `Cha_X 章名` / `CX Sec_X 节名.md` / `CX 速查.md` / `CX 测试.md`；没有残留的 `CX-NN 名称.md` 概念文件
- [ ] 所有链接的目标文件存在、锚点对得上标题；无空链接；无指到根目录之外的链接
- [ ] 所有图片文件存在
- [ ] 无 `[[wikilink]]`、`![[嵌入]]`；无 `> [!note]`、`> **Note**:` 旧式标注（warning 也要清掉）
- [ ] 块级公式 `$$` 各占一行
- [ ] 每篇笔记 frontmatter 有 `subject`、`chapter`、`status`、`tags`（`checklist.md` 豁免）
- [ ] 每节练习 3–5 题；`notes_data.js` 里每节 `quiz` 3–5 题
- [ ] `<!-- source: -->` / `<!-- output: -->` 绑定的内容逐行能在对应文件里找到
- [ ] 每章测试满分恰为 100，各题分值之和 = 100，客观题 ≥ 60 分
- [ ] `notes_data.js` 可解析；`file` 路径与真实文件逐字符一致；md 与 js 题目对应
- [ ] 无残留 `{{占位符}}`
- [ ] [R1][R2][R5][R10] 每节：三行导读（手上 / 结束时 / 本节要回答）、承接块、3–5 步（每步有动作 / 结果 / 为什么）、小结、练习、概念索引、留给下一节；预计用时 30–100 分钟
- [ ] [R3] 概念写法全库统一，没有连排的 `## 概念`
- [ ] [T1]–[T5]（2.1 版只报 warning）：每步先讲后做（动手前 ≥ 8 行讲解、标题是问题不是文件操作）；概念 40–120 行且讲了「为什么需要它」与原理/数学；每节至少一处先想/先猜并解释猜错的人错在哪；每步有「刚才发生了什么」回看；正文行数 ≥ 代码行数。写新库时按硬要求执行，别把它当"可有可无"
- [ ] [R4] 代码块都有标签且路径在 `project/` 下；照做重放成功；每章重放结果与 `code/answer/chNN/` 同构；不引用晚于本章的答案或 notebook；没有让读者在 `code/` 里动手
- [ ] [R6][R7] 每章最后一节有章末通跑（【运行】+ 真实输出）和本章项目地图
- [ ] [R8] notebook 在 `code/notebooks/CN_*.ipynb`，不带输出
- [ ] [R11] 正文、命令、输出里没有本机绝对路径
- [ ] `run-course.mjs`：每个【运行】的真实输出与绑定文件一致

需要逐条判断的 warning：老库（不加 `--strict`）的 [R*] 课程线规则、讲解线规则 [T1]–[T5]、篇幅超 800 行、标注块超 20 个、旧式概念编号（`C1-01`）残留、缺 `CX 速查.md`、第 3 章起测试缺 `【回顾 CX】`、写了「真实输出」却没绑定、链接路径含未编码空格。能修的都修；不修的在 `checklist.md` ⑤ 写明原因。

## 三、人工红线（脚本查不了，必须亲自确认）

- [ ] **Typora 实看**：抽 2–3 篇在 Typora 里打开（或请用户打开），标注块标签可见、公式成块显示、表格不乱、链接能点开
- [ ] **门户离线可用**：断网时导航、阅读、测试、速查、进度功能完整（公式降级为源码样式可接受）
- [ ] **启动脚本可用**：双击 `启动学习服务器.bat` 能起服务器并打开浏览器；端口被占用时自动换端口
- [ ] **顺读测试通过**：至少一章按 `teaching-design.md` 第十二节的操作定义，从空的 `project/`（或白纸）照正文字面做到章末，不看 `code/`、不跳读、不补步骤；每一步结果与正文一致，章末通跑通过。卡住的位置写进 `checklist.md` 并修掉
- [ ] **每节产物可验证**：抽 3 节，读者读完能说出本节在 `project/`（或推导本、句子本……）里多了什么，并且有办法自己判断它对不对（跑一条命令、验算一行、默写一句、对照一段原文）
- [ ] **教学设计**：抽 3 节，对照 `teaching-design.md` 第十三节自查清单（三行导读、问题式步骤、四拍「想讲做看」、概念就地出现且讲透、坏掉时刻、学习目标 ↔ 练习、先猜后看）
- [ ] **遮住代码再读一遍**：抽 3 节，把代码块全部遮掉，只读剩下的正文——能不能读成一篇完整的小课（提出问题 → 原理与数学 → 结论），还是只剩一堆"接下来新建 X"。只剩骨架的，回去补讲解
- [ ] **题目可解**：抽 3 道题（含 1 道主观题），题干自洽、答案确实是最优解、解析说清"为什么错"
- [ ] **测试判分**：在门户里做完一套测试，客观题判分正确、主观题能自评、成绩被保存、重测保留最近与最佳
- [ ] **难度渐进**：从第 1 章和第 N 章各读一节，后者确实建立在前面之上，没有用到未讲的概念，也没有用到读者 `project/` 里还不存在的文件或函数
- [ ] **间隔复习**：第 3 章起的测试回顾题覆盖至少两个旧章节，且考的是本章会用到的旧知识
- [ ] **速查可用**：速查只含已讲内容，每条能链回正文
- [ ] **风格统一**：所有节笔记骨架一致（问题式步骤、每步四拍「想讲做看」、概念写法统一），符合样章确认时的约定
- [ ] **无装饰性灌水图**：每一张图都确实在解释某件事

## 五、自检记录

在 `checklist.md` 末尾追加「⑤ 交付自检」。下面是代码类课程的例子；非代码科目把「真实运行」「抽查代码」换成本科目的验证方式（如从头验算推导本），没有就省略：

```markdown
## ⑤ 交付自检

- 校验脚本：`node .../check-library.mjs "<根>" --strict` → 0 error / N warning（逐条说明保留原因）
- 真实运行：`node .../run-course.mjs "<根>"` → 37 条【运行】全部一致
- 顺读测试：第 3 章从空 `project/`（由 `code/answer/ch02/` 复制）照做到章末通跑 ✅；C3 Sec_2 第 2 步原来缺一行 import，已补
- 遮罩测试：遮住 C1 Sec_1 的全部代码块，正文仍能读成一篇完整的小课 ✅
- Typora 实看：C1 Sec_1、C4 Sec_2、C7 速查 ✅
- 抽查公式：C3 Sec_2 的 3 处推导已逐步复核 ✅
- 抽查代码：第 4 章【重构】`backward` 的理由与真实输出一致；`code/answer/ch04/` 与重放同构 ✅
- 门户实测：完成 C1 测试 → 得分 85，重测 92，best/last 正确记录 ✅
- 已知局限：第 5 章某定理省略了引理证明，已在文中标注"引理证明不在本课程范围"
```

**已知局限要写出来，不要藏。** 诚实的边界比虚假的完整对学习者更有价值。
