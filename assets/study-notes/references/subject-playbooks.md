# 分科目教学打法

《学习笔记生成准则》的科目是中立的。这一篇补上"这类科目到底该怎么教"。**先在这里找到最接近的一类，再动手。**

判断方法：问自己"这门科目的**核心能力**是什么？"。是**推导**？**构造**？**记忆与调用**？**论证**？**操作**？找到那一栏，就找到了练习与测试该怎么出，也就找到了**每节产物**是什么。

---

## 通用：先定四件事

1. **记号与约定表（Notation sheet）**：在第 1 章或大纲附录里放一张全库通用的记号/术语表。之后每一节都遵守它。这是防止"同一个符号在第三章变了意思"的唯一办法。
2. **比喻体系**：选**一套**贯穿全库的比喻（如"工具箱与零件""建筑与脚手架""地图与路线"），不要每节换一套。比喻负责直觉，定义负责严谨，两者都要有、不要混。
3. **难度标尺**：在大纲的每章标注难度（入门 / 进阶 / 挑战），并在正文里诚实标注"这一节是整个课程最难的一节，允许读两遍"。
4. **每节产物（R9）**：读者手里那份一节节变厚的东西是什么。代码类科目是 `project/`；其他科目见下面各节的「每节产物」一行。它要满足三条：<b>累积</b>（这一节在上一节的基础上加）、<b>可检验</b>（读者自己能判断对不对：跑、验算、默写、对照原文）、<b>可修改</b>（后面的节会回头改它）。导读里的 <b>你现在手上</b> / <b>本节结束时</b>、步骤里的 `<b>动手</b>：…` 和 `<b>你应该看到</b>：…`，都是对着这份东西写的。

非代码科目没有【新建】/【修改】标签，步骤写成 `<b>动手</b>：在推导本第 3 页写下……` + `<b>你应该看到</b>：……`；章末通跑写成「从头验算 / 默写 / 复述一遍」，项目地图写成这份东西的目录（推导本有哪几页、句子本有哪几组）。

> <b>*Note*</b>
> 关于下面各科目的「练习」一行
>
> 每节练习是 **3–5 题**（见 `teaching-design.md` 第七节）。下面列出的三种题型是前 3 题的默认组合；需要第 4、5 题时，出综合题（串起本节多个概念）或连接前面章节的题。具体每节几道，以样章确认时用户的选择为准。

## 一、数学 · 理论物理 · 形式科学

**核心能力：推导。**

- **大纲**：按"定义 → 性质 → 定理 → 应用"的依赖顺序排。**依赖顺序优先于历史顺序**。数论、代数、分析、概率等各自成章。
- **节笔记**：
  - 每个新概念先回答"**它想解决什么问题**"（历史上为什么被发明），再给定义。
  - 定义用 `> <b>*Note*</b>`，把**量词**写全（$\\forall \\varepsilon>0\\ \\exists \\delta>0$ 这样的结构不要省略）。
  - 定理必须写清**条件**与**结论**，并给一个**反例**说明去掉条件为什么不成立。
  - 推导逐步写，每步标注依据（"由三角不等式""两边同除 $x$，因 $x\\ne0$"）。
  - 公式一律 `$$...$$` 独立成行；多步推导用 `\\begin{aligned}` 对齐。
- **每节产物**：
  - <b>推导本</b>：读者自己的一份推导记录，每节加几页（定义 → 引理 → 本节定理的完整推导），后面的节会引用、修正前面的页。步骤写成「在推导本上写下第 2 行，依据是……」，结果是读者应该得到的那一行式子。
  - <b>反例集</b>：每个定理的每个条件配一个"去掉它就不成立"的反例，逐节累积。坏掉时刻就从这里来：先让读者用一个"显然对"的说法，再给反例打破它。
  - <b>验算脚本</b>（可选）：一小段读者自己写的数值验算（Python / 计算器步骤），用来核对推导结果，放在 `project/` 里，同样按【新建】/【修改】写。
  - 章末通跑：从推导本第 1 页开始把本章推导从头验算一遍；项目地图是推导本的目录。
- **图**：函数图像、几何构造、集合关系用 Mermaid；实数轴/区间用文本图；**不要**用装饰性插图。
- **练习**：1 题直接套定义、1 题需要一步变形、1 题辨析（判断某个"显然"的命题为假并给反例）。
- **测试**：选择/判断/填空 ≥ 60 分（概念辨析最适合），计算题给步骤分，证明题给评分要点（"写出归纳假设 3 分；完成归纳步骤 7 分"）。
- **毕业设计**：给 3–5 个"用本课程工具解决一个完整问题"的题目（如"用线性代数方法做图像压缩并解释每一步"），要求写出完整推导 + 数值验证。
- **易犯错误**：跳步；符号前后不一致；把"存在"当"任意"；忘记定义域/边界条件。

## 二、编程 · 软件工程 · 算法

**核心能力：构造。**

- **大纲**：按"能跑起来的最小闭环 → 逐步加能力"排，而不是按语言特性列表排。第 1 章就要让用户写出能运行的东西。
- **每节产物**：读者自己的 `<根>/project/`，从空目录开始，每节加几个文件或改几处。`code/answer/chNN/` 是第 N 章做完时它应有的样子。
- **节笔记**：
  - 每一步都是读者能照做的动作：【新建】整份文件、【修改】定位式 diff、【重构】整个函数、【运行】命令。格式见 `notes-standard.md` 5.4。不要从写好的成品代码里摘片段。
  - 给出**真实输出**：用 `scripts/run-course.mjs --write` 在照做重放的快照里运行并保存，正文前写 `<!-- output: … -->`；关键输出先让读者猜（先猜后看）。
  - 至少一次**坏掉时刻**：一个真实的报错或失败的测试，并解释为什么错、怎么修（这是最有价值的部分）。
  - 准备一个"草稿纸"脚本（如 `project/check.py`），每加一个功能就往里加一两行打印，读者随时能跑。测试从第 1 章就开始写，章末通跑就是"跑全部测试"。
  - 演示性质的东西（调参数看现象、画图）放 `code/notebooks/CN_主题.ipynb`，不带输出；框架代码只进 `project/`。
  - 代码块**必须标注语言**；伪代码标 ```text```。
  - 复杂度、边界条件、常见坑用 `> <b>*Warning*</b>`。
- **图**：数据结构、内存布局、调用栈、状态机、算法流程用 Mermaid（`flowchart` / `sequenceDiagram` / `stateDiagram-v2` / `classDiagram`）。执行过程用**带注释的代码 + 逐步输出**，比图更有效。
- **练习**：1 题读代码说输出、1 题改 bug（给出有 bug 的代码）、1 题自己写一个小函数（给出测试用例与期望输出，便于自评）。
- **测试**：选择/判断/填空 ≥ 60 分；编程题给**完整参考实现 + 测试用例 + 评分要点**（"能通过样例 8 分；处理空输入 4 分；复杂度达标 3 分"）。
- **毕业设计**：**必须是一个完整可运行的小项目**，从最后一章的 `project/` 出发，并逐处标注各章节知识在其中发挥作用（`# 见 C3 Sec_2 递归`）。给完整代码 + 运行说明 + 可扩展方向。
- **易犯错误**：
  - 示例代码不可运行；用 `...` 省略关键逻辑；只讲 API 不讲为什么这么设计；不提复杂度与边界。
  - <b>读者不知道文件放哪</b>：代码块没写文件路径，或者让读者在 `code/`（示例仓库）的位置里 `mkdir`。读者要么不敢动，要么把答案区改坏。每个代码块都带【新建】/【修改】标签和 `project/` 路径。
  - <b>示例代码是别人的</b>：先把成品写进 `code/`，正文再"节选"几段。读者手里没有一行是自己敲出来的，照着节选敲也跑不起来；成品里还提前露出了后面几章才写的方法。代码只能从读者自己的 `project/` 里长出来，`code/answer/` 只放每章结束时的快照。
  - <b>演示代码塞进 .py</b>：为了展示一个现象（广播、浮点误差）在框架里新建 `demo_xxx.py`，越积越多，分不清哪些是框架、哪些是玩具。演示放 `code/notebooks/CN_主题.ipynb`，一格一件事，不带输出。

## 三、自然科学（物理 · 化学 · 生物 · 地球科学）

**核心能力：从原理到现象的双向映射。**

- **大纲**：按"现象 → 模型 → 定量关系 → 应用"排。
- **节笔记**：
  - **单位与量纲**必须写；每个公式后跟一句量纲检查。
  - 每个定律给：**文字表述 + 公式 + 适用条件 + 一个生活现象解释**。
  - 图：受力/场线/能级/反应路径/系统结构用 Mermaid 或矢量图源；**定量关系优先给表格与函数图像**。
  - 实验相关内容写清：目的、器材、步骤、**安全注意**（`> <b>*Warning*</b>`）、预期现象、误差来源。
- **每节产物**：一本<b>观测与估算记录</b>：每节加一个现象的「预测 → 观测或数据 → 用本节公式解释 → 量纲检查」，后面的节用新模型回头修正前面的解释。能动手做的实验写成 `<b>动手</b>：…` + `<b>你应该看到</b>：…`；需要计算的用 `project/` 里的小脚本，同样按标签写。
- **练习**：1 题套公式（含单位换算）、1 题估算/数量级、1 题解释现象或设计实验。
- **测试**：选择/判断/填空 ≥ 60 分；计算题要求**带单位**并给步骤分；简答题给评分要点（"提到 X 给 2 分，解释 Y 给 3 分"）。
- **毕业设计**：设计并分析一个实验/观测，或对某个真实数据做定量建模。
- **易犯错误**：单位漏写或混用；公式适用条件不写；把模型当真理。

## 四、语言学习（外语 · 古文 · 语言学）

**核心能力：记忆 + 调用（输入 → 输出）。**

- **大纲**：按"使用场景 + 语法难度"双轴排。**不要**按语法书目录从头抄到尾——那样学到第 5 章还不能说一句话。前期安排"能立刻用上"的内容。
- **节笔记**：
  - 核心是**可查询的表**：词表（词 / 音标或拼音 / 词性 / 释义 / 例句）、变位表、句型表。表格是这一科目的主要"图"。
  - 语法点讲"**什么时候用**"和"**和它容易混的那个**"，配**对比例句对**。
  - 例句必须**短、真、可替换**（给一个模板 + 3 个替换练习）。
  - 发音/语调用文字描述 + 类比（"像汉语的第三声但更短"）；**不要**假装能用文字精确描述音值。
- **图**：语法结构树、时态/体貌的时间轴对比、流程图（"想表达 X 用哪个句型"）用 Mermaid。
- **每节产物**：
  - <b>句子本</b>：读者自己的一组句子，每节加 5–10 句（用本节句型替换出来的），后面的节回头改写它们（换时态、加从句）。步骤写成「在句子本上把第 3 句改成过去时」，结果是正确的句子与可接受变体。
  - <b>作文</b>：一篇从第 1 章开始写的短文，每章扩写一段，用上本章的语法与词汇。
  - <b>听写 / 默写</b>：每节末尾默写本节句子本里的句子，章末通跑就是整章默写一遍。
  - 项目地图是句子本的目录：第几组句子练的是哪个句型。
- **练习**：1 题填空/变位、1 题翻译（中→外，给参考答案与可接受变体）、1 题造句/改错。
- **测试**：选择/判断/填空占绝大多数（≥ 70 分）；翻译与写作给评分要点与范文。
- **毕业设计**：写一段真实的自我介绍/短文/对话，或完成一次主题词汇网络整理（含例句与场景）。
- **易犯错误**：只给规则不给使用场景；例句很长很假；不标音；不给可接受变体导致用户以为自己错了。

## 五、人文社科（历史 · 哲学 · 经济 · 法律 · 社会学）

**核心能力：论证与辨析。**

- **大纲**：按"时间 / 主题 / 学派"选一个主轴（历史用时间，哲学用问题，法律用部门法），另一个作为穿插。
- **节笔记**：
  - 每个观点必须**并列呈现不同立场**，并说明各自的前提与代价。**不要**把有争议的问题写成定论。
  - 关键概念给"**定义 + 谁提出的 + 反对意见**"。
  - 事件/主张用**时间线**（Mermaid `timeline`）或**论证结构图**（前提 → 推理 → 结论）。
  - 引用原文时给出处；不确定出处就不要引。
  - `> <b>*Tip*</b>延伸：……` 用于原文摘录与延伸阅读（`quote` 不在允许的 5 种里）。
- **图**：时间线、因果链、学派对照表、论证结构图。**表格在这里比图更重要**。
- **每节产物**：
  - <b>时间线</b>：读者自己的一条时间线，每节加几个事件与因果箭头，后面的节回头修正"原来这件事的原因不是这个"。
  - <b>论证稿</b>：一篇从第 1 章开始写的小论点短文，每节加一个论据或一条反驳，章末重写一遍。
  - <b>对照表</b>：学派 / 立场 / 制度的对照表，每节加一行或一列。
  - 坏掉时刻：给一段材料，让读者先用已有的论点解释，再发现解释不通。章末通跑是把时间线或论证稿从头复述一遍。
- **练习**：1 题概念辨析、1 题史料/材料分析（给一段材料，问它支持哪个观点）、1 题短论述（给评分要点）。
- **测试**：选择/判断/填空 ≥ 60 分（适合考事实与概念边界）；论述题给**评分要点 + 分档标准**（"能并列两方观点 5 分，能指出各自前提 5 分，有独立判断 5 分"）。
- **毕业设计**：写一篇有小论点的短文，或做一份"某议题的多方立场对照 + 自己的判断"。
- **易犯错误**：把争议写成定论；只给结论不给论证；年代/人名出错；引文编造。

## 六、操作型科目（实验 · 工程 · 医学 · 临床 · 运维）

**核心能力：安全、正确地完成操作。**

- **大纲**：按"操作流程的依赖 + 风险等级"排；**高风险操作必须先讲原理与后果**。
- **节笔记**：
  - 流程用**编号步骤**，每步写清：动作、参数、预期观察、**出错时怎么办**。
  - 安全检查单独一块 `> <b>*Warning*</b>`，放在流程**之前**。
  - 参数必须给**单位、正常范围、超限后果**。
  - 故障排查用**决策树**（Mermaid `flowchart`）。
  - 配**真实案例**：有输入有输出、有问题有结局（这是本类科目最有效的教学形式）。
- **每节产物**：一份<b>操作清单与故障排查表</b>：每节加一段流程或一个故障分支，后面的节在上面补参数、补例外。能在安全环境里实际操作的写成 `<b>动手</b>：…` + `<b>你应该看到</b>：…`。
- **练习**：1 题流程排序/参数选择、1 题故障定位（给现象，问最可能的原因与下一步）、1 题案例判断。
- **测试**：选择/判断/填空 ≥ 60 分（适合考安全与参数）；案例分析题给评分要点，以"判断 + 依据 + 处置"三段给分。
- **毕业设计**：完成一次完整操作方案设计（含风险评估与回退方案），或对一份真实案例做全流程复盘。
- **易犯错误**：安全提示写得含糊；参数没有单位；只讲正确路径不讲出错处置。

## 七、应试型备考（考研 · 考证 · 竞赛 · 期末）

**核心能力：在限定时间内拿到分。**

- **大纲**：**按考纲与题型排**，不按学科逻辑排。先摸清"考什么、怎么考、多少分"。
- **节笔记**：
  - 每节开头用 `> <b>*Note*</b>本节导读` 写清"**本节对应考纲哪一条、历年考频、题型**"。
  - 每个知识点后跟"**考法**"：会以什么形式出现、常见陷阱选项长什么样。
  - 收录**真题风格例题**（可改编，但必须标注"改编"）。
  - `> <b>*Tip*</b>` 放记忆口诀、答题模板、时间分配建议。
  - `> <b>*Warning*</b>` 放**高频错点**与评分细则里的"不写不得分"项。
- **图**：知识体系图（Mermaid `mindmap` 或 `flowchart`）、题型决策树、公式速查表。
- **每节产物**：一本<b>错题本 + 答题模板</b>：每节加几道真题风格题的完整作答与错因，后面的节用新方法重做前面的错题。章末通跑是限时做一套本章小卷。
- **练习**：全部用**考试题型**。1 题基础得分题、1 题常见陷阱题、1 题综合题。
- **测试**：**严格按真题卷面结构**出（题型、题量、分值分布、时长）。答案给评分细则，明确"写哪些关键词得几分"。
- **毕业设计**：整套模拟卷 + 答题时间分配方案 + 错题归因表。
- **易犯错误**：只讲知识不讲考法；难度与真题不匹配；不给时间分配建议。

## 八、跨科目通用：怎么选毕业设计

好的毕业设计选题满足四条：

1. **用得上全课程**：需要至少 3 个不同章节的知识才能完成。
2. **有明确完成标准**：用户能自己判断"我做完了没有"。
3. **分层**：3–5 个选题，从"巩固型"（把课内例子做一遍并扩展）到"挑战型"（需要自己查资料、做取舍）。
4. **有示例**：给参考答案、示例实现或评分要点——**但不能只给答案不给过程**。

选题命名示例：

| 类型 | 数学 | 编程 | 历史 |
|---|---|---|---|
| 巩固型 | 用本章方法重做课本例题并验证 | 实现课内数据结构的完整版本 | 整理某一事件的年表并标注因果 |
| 综合型 | 用两章工具解决一个建模问题 | 做一个小工具，用到 3 个章节的知识 | 就一个议题做多方立场对照 |
| 挑战型 | 证明一个未在课内给出的命题 | 从零实现一个能跑的小系统 | 写一篇有小论点的短论文 |
