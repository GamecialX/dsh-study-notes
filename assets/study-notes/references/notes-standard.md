# 笔记标准（结构、命名、Markdown 格式）

本文是笔记**格式**的唯一规范；**怎么教**见 `teaching-design.md`。SKILL.md 的「七条铁律」是两者的摘要，冲突时以铁律为准。

<b>示例的适用范围</b>：本文里的示例（`project/`、minigrad、【新建】/【修改】标签、文件树等）取自代码类、计算机类、AI 类课程，专供这类任务参考。其他科目只要满足本规范的其他条款，步骤怎么切、产物长什么样、例子怎么选都有自由空间，按 `subject-playbooks.md` 里对应科目的打法来，不必向这些示例靠拢。

目标环境：用户主要用 **Typora** 阅读。所有写法都必须在 Typora 里显示正确，同时在 VS Code、GitHub、Pandoc 和门户里不丢内容。

---

## 一、定位

学习笔记是**一条能从上读到下、边读边做的课**：用户从一个空文件夹（或一张白纸）出发，照着每节的几步做下去，手里的东西一节节长出来，最后学会。它像笔记一样好读，但不必遵守教科书体例（不要"本节教学目标"式的官腔），也不是按概念排列的百科。

- 允许口语化、比喻、「编者按」式吐槽。
- **知识本身必须严谨**：定义不含糊、公式不跳步、代码能跑、案例数据自洽。
- 目标是"真的学会"，不是"看起来覆盖了"。
- 概念是课程线上的节点，在第一次需要它的地方出现；它不是组织全书的单元。

## 二、文件结构与命名

```
<根>/
├── 00 大纲.md
├── checklist.md
├── project/                  ← 读者自己的工程：从空目录开始，照正文一步步长出来（你不往里放东西）
├── code/                     ← 答案与证据（代码类科目）
│   ├── answer/ch01/          ← 第 1 章做完时 project/ 应有的样子，与 project/ 同构
│   ├── out/                  ← 每次【运行】的真实输出
│   └── notebooks/C1_*.ipynb  ← 演示用 notebook，不带输出
├── web/{index.html, notes_data.js, serve.mjs}
├── 启动学习服务器.bat
├── start_server.sh
├── Cha_1 章名/
│   ├── C1 Sec_1 节名.md      ← 节笔记（3–5 步；概念是步骤里的 ### 条目）
│   ├── C1 Sec_2 节名.md
│   ├── C1 速查.md            ← 本章速查（一页纸）
│   ├── C1 测试.md            ← 章末测试
│   └── src/*.png
└── Cha_2 章名/...
```

| 类型 | 命名规则 | 示例 |
|---|---|---|
| 章文件夹 | `Cha_X 章名` | `Cha_2 矩阵与线性方程组` |
| 节笔记 | `CX Sec_X 节名.md` | `C2 Sec_3 矩阵乘法.md` |
| 本章速查 | `CX 速查.md` | `C2 速查.md` |
| 章末测试 | `CX 测试.md` | `C2 测试.md` |
| 图源 | `Cha_X 章名/src/文件名` | `Cha_2 矩阵与线性方程组/src/matmul.png` |

- `X` 是阿拉伯数字章号，不补零（`Cha_1`，不是 `Cha_01`）。
- 名称中可以有空格与中文标点；不要用 `/ \ : * ? " < > |`。
- 节笔记的 H1、文件名、`notes_data.js` 里的 `title` 三者**逐字符一致**（含全半角）。
- 以 `_` 或 `.` 开头的目录（如 `_维护/`）是维护区，校验器跳过。`project/`、`code/`、`web/` 也不是章目录。
- **概念不另立文件**，也不当节的骨架：写成步骤里的 `### 概念 N：名称` 条目（见第六节）；不要再用 `C1-01` 这类编号指代概念。
- `code/answer/chNN/` 的章号补零到两位（`ch01`），notebook 用 `CN_主题.ipynb`（`C3_广播.ipynb`，N 是第一次用到它的章）。
- 正文、命令、输出里只写相对路径（相对笔记根目录或 `project/`），不写本机绝对路径（R11）。

> <b>*Note*</b>
> 为什么不再"一个概念一个文件"
>
> 早期版本把每个概念拆成独立文件（`C2-03 矩阵的秩.md`），靠 Obsidian 的双向链接串起来。这有两个硬伤：一是绑定编辑器，换到 Typora 跳转就失效；二是阅读碎片化，读一段话要跳出去再跳回来。后来改成"概念就地成节"，但节仍然是一串 `## 概念 N` 的拼接，读者读完不知道手上该有什么。现在的结构是：节由步骤组成，概念是步骤里的条目，跳转仍然只有两种标准 Markdown：文件之间与文件内部（锚点）。

## 三、Frontmatter

每篇笔记顶部写 YAML frontmatter：

```yaml
---
subject: <科目名>
chapter: <章号>
section: <节号>
status: 未开始         # 未开始 | 学习中 | 已完成
tags: [<科目名>, 节笔记]
---
```

- `status` 由用户手动维护，生成时一律写 `未开始`。
- 速查与测试省略 `section`，`tags` 末项分别写 `速查`、`章末测试`；大纲写 `chapter: 0`、`大纲`。
- `subject` 全库一致。
- `checklist.md` 是工作记录，**不加 frontmatter**，校验器豁免。
- 只用通用字段，不写编辑器专有的键（如 `aliases`、`cssclass`）。

## 四、标注块

### 4.1 写法

标注块 = **普通引用块 + HTML 加粗斜体标签**。标签独占一行、不带冒号；标题写在下一行；正文与标题之间空一行（写作 `>`）：

```markdown
> <b>*Note*</b>
> 本节导读
>
> 正文内容……
```

| 标签 | 用途 |
|---|---|
| `<b>*Note*</b>` | 定义、核心结论、说明、导读、答案 |
| `<b>*Tip*</b>` | 直觉、技巧、口诀、想一想、先猜一猜、要点清单 |
| `<b>*Important*</b>` | 必须记住的约束、全章最关键的一句话 |
| `<b>*Warning*</b>` | 易错点、常见误区、前置依赖提醒 |
| `<b>*Caution*</b>` | 危险操作、反例、会产生错误结果的做法 |

语义差别写在**标题**里，用中文说清，不要再加"导读："这类前缀：

| 你想要的语义 | 标签 + 标题 |
|---|---|
| 节导读 | `Note` + `本节导读` |
| 定义 | `Note` + `<术语> 的定义` |
| 案例 | `Note` + `案例：<标题>` |
| 思考题 | `Tip` + `想一想` |
| 先猜后看 | `Tip` + `先猜一猜` |
| 要点清单 | `Tip` + `记住这些` |
| 练习答案 | `Note` + `答案与解析` |
| 存疑 | `Warning` + `此处存疑` |

规则：

- 引用块内的**每一行**都以 `>` 开头，空行写作 `>`，否则块会断开。
- 只用这五种标签；不要写 `> [!note]`（callout），也不要写 `> **Note**:`。原因见 `editor-compatibility.md`。
- 正文里需要加粗时同样用 `<b>…</b>`：用户的 claudette 主题不显示 `**粗体**`。表格里的 `**粗体**` 不影响阅读，但新写的内容统一用 `<b>`。
- 门户会把这种标注块渲染成彩色标注框，并把标题为「答案与解析」「参考答案」的块默认折叠。
- 每节标注块数量有预算（见 `teaching-design.md`）。

### 4.2 答案与解析

每道练习后紧跟一个答案块：

```markdown
**2.** 题干……

> <b>*Note*</b>
> 答案与解析
>
> <b>答案</b>：B
>
> <b>解析</b>：……
```

旧写法 `例：答案与解析` 仍能被校验器和门户识别，新内容不要再加「例：」。Typora 里引用块不能折叠，所以答案块要紧跟在题目下面、与下一题之间用空行隔开。

### 4.3 引用块里的公式

块级公式放进引用块时，公式每一行也要带 `>`，`$$` 各占一行：

```markdown
> <b>*Note*</b>
> 梯度的定义
>
> $$
> \nabla f = \left(\frac{\partial f}{\partial x_1}, \dots, \frac{\partial f}{\partial x_n}\right)
> $$
```

## 五、链接、图片、公式

### 5.1 链接

```markdown
[显示文字](C1%20Sec_2%20%E5%9F%BA%E6%9C%AC%E5%85%B3%E7%B3%BB.md)                文件跳转（同章）
[显示文字](../Cha_2%20%E8%BF%9B%E9%98%B6/C2%20Sec_1%20%E5%B7%A5%E5%85%B7.md)    文件跳转（跨章）
[显示文字](C1%20Sec_1%20%E5%9F%BA%E6%9C%AC%E5%AF%B9%E8%B1%A1.md#概念-1-基本对象)  文件 + 锚点
[显示文字](#概念-1-基本对象)                                                     本文件内锚点
```

- 路径按**当前文件所在目录**解析。`00 大纲.md` 在根目录，链接节笔记要带章目录：`Cha_1%20…/C1%20Sec_1%20….md`；跨章链接用 `../Cha_2 …/`。
- 路径含中文、空格、全角括号时百分号编码（`encodeURI`）。未编码的空格会让 Typora / Pandoc 截断链接。
- 锚点部分可以直接写中文，不必编码。
- 禁止空链接 `[文字]()`、禁止指到笔记根目录之外、禁止 `[[wikilink]]`。
- **锚点规则**：标题转小写 → 去掉 `` ` `` `*` `_` `~` `[` `]` `(` `)` → 其余连续的空格和标点换成一个 `-` → 去掉首尾 `-`。
  例：`### 概念 1：张量 Tensor 与 ndarray` → `#概念-1-张量-tensor-与-ndarray`（`##` 和 `###` 算法一样）。
  Typora 与 GitHub 对 `▸`、`·`、`：` 等符号的处理略有差异；校验器只要"去掉所有非字母数字后与某个标题一致"就算命中。为了稳妥，**链接的标题里尽量不放装饰符号**。
- 标题定稿后不要随意改：锚点由标题算出，改了标题要同步改所有指向它的链接（概念索引、大纲、速查）。

### 5.2 图片

```markdown
![图的说明](src/matmul.png)
```

- 图源放该章 `src/`，用相对路径引用。禁止 `![[文件名.png]]`。
- 图必须准确服务于讲解，禁止装饰性灌水图。流程、结构、关系类内容优先用 Mermaid：

````markdown
```mermaid
flowchart LR
  A[输入] --> B{判断} -->|是| C[处理]
```
````

Mermaid 在 Typora、GitHub、VS Code 里原生渲染；门户里显示为代码卡片是可接受的降级，所以正文必须能脱离图读懂。

### 5.3 公式

| 形态 | 正确写法 | 错误写法 |
|---|---|---|
| 行内 | `$f'(x)$`，与文字同一行 | `\(...\)` |
| 块级 | `$$` ⏎ 公式 ⏎ `$$`，定界符各占一行 | `$$公式$$` 挤在一行；单个 `$` 当块级定界符 |

挤在一行时 Typora 会把源码原样显示。列表项里的块级公式要带列表缩进：

```markdown
- 第 2 步：
  $$
  E = mc^2
  $$
```

公式夹在句子中间时保持行内，不要为了"套块级"把句子拆成三行。

### 5.4 代码块、标签与输出

代码类科目里，读者看到的每个代码块都要回答两个问题：<b>它住在哪个文件</b>、<b>是整份还是只改一处</b>。所以正文（第 1 步到最后一步之间）的代码块一律带标签。标签独占一行，以【】开头，后面第一个行内代码是 `project/` 下的路径，下一个块就是它的内容：

| 标签 | 代码块里放什么 | 规则 |
|---|---|---|
| 【新建】`project/路径` | 整份新文件 | ≤ 120 行；不许省略；照做到这里这个文件还不存在 |
| 【修改】`project/路径` | ```` ```diff ````：改动行以 `-` / `+` 开头，上下各留 1–2 行原样的上下文（行首一个空格） | 上下文在当前文件里必须恰好出现一次 |
| 【重构】`project/路径` | 一个完整的函数或类（含原有缩进） | 按名字整块替换同名的 `def` / `class` / `function`；正文写清为什么换 |
| 【收口】`project/路径` | 整份文件此刻应有的样子（可只写标签不给块） | 必须与照正文做到这里的结果一字不差；放在一步或一章的末尾，供读者自查 |
| 【运行】 | ```` ```bash ```` 等命令块 | 标签文字里写 `project/`（如「【运行】在 `project/` 里：」）表示在 `project/` 里执行，否则在笔记根目录 |

````markdown
【修改】`project/minigrad/__init__.py`：让 `minigrad.numeric_grad` 能直接用。

```diff
 """minigrad：从零手搓的自动求导小框架。"""

+from .numeric import numeric_grad
+
 __version__ = "0.1.0"
```

【运行】在 `project/` 里：

```bash
python check.py
```

<!-- output: code/out/c1s1-2.txt -->
```text
minigrad 0.1.0
d(x*x)/dx at x=3: 6.000000000039306
```
````

- 【运行】后面紧跟 `<!-- output: code/out/….txt -->` 和输出块。输出文件是**运行后保存的真实结果**，不要手写；用 `scripts/run-course.mjs --write` 在照做重放的快照里运行并保存，保存时本机绝对路径会被去掉（R11）。
- 不许「节选」、不许 `# ...` / `// ...` 省略行、不许裸代码块。读者照敲必须能跑。
- 伪代码、公式推导里的代码样子的东西标 `text`。概念条目里的例子不需要标签，但要是能跑的代码，就放进某一步的【新建】/【修改】里。
- 第 N 章结束时，照正文从空目录做出来的 `project/` 必须与 `code/answer/chNN/` 逐文件一致；`run-course.mjs --write` 会从重放结果生成它。下一章从上一章的答案出发重放。
- notebook 放 `code/notebooks/CN_主题.ipynb`：一格一件事、不带输出、只做演示，不写框架代码。正文写一句 <b>动手</b>：打开 `code/notebooks/CN_主题.ipynb` 来引用它，不需要输出绑定。
- 正文不许引用晚于本章的 `code/answer/chNN/` 或 `code/notebooks/CN_*`。

<b>老库兼容</b>：老库用 `<!-- source: code/xxx.py -->` 从成品代码里摘片段，校验器仍会逐行核对它（片段里的每个非空行都必须在来源文件里），但这种写法不告诉读者代码住在哪、怎么从无到有，新库不要再用。迁移方法见 README「老库怎么按新结构逐步迁移」。

## 六、节笔记骨架

骨架全库统一，模板见 `templates/section-note.md`。一节是一条施工线：从读者手上已有的东西出发，3–5 步把它推进一截。必备环节按顺序：

1. Frontmatter
2. `# CX Sec_X 节名`（整篇唯一的 H1）
3. **导读**：`本节导读` 标注块，必须有两行
   - `<b>你现在手上</b>：…`：上一节结束时读者的 `project/`（或推导本、句子本……）里有什么、能做到什么、做不到什么；
   - `<b>本节结束时</b>：…`：多了哪几个文件 / 哪几条式子，多能做到什么。
   然后是 2–4 条学习目标、前置（带链接）、`<b>预计用时</b>：N 分钟`（30–100）、难度。
4. `## 接上一节`：三行，`<b>上一节做到</b>：…`、`<b>留下的坑</b>：…`、`<b>本节补上</b>：…`。全课第一节写「这是第一节」并说明本节要造的第一样东西。
5. `## 第 1 步：<动词短语>` … `## 第 N 步：<动词短语>`，N 为 3–5，编号连续。标题是动作（「把核对写成测试」），不是名词（「单元测试」）。每一步按这个顺序写：
   - <b>动作</b>：【新建】/【修改】/【重构】/【运行】，或非代码科目的 `<b>动手</b>：…`；
   - <b>可见的结果</b>：绑定的真实输出，或 `<b>你应该看到</b>：…`；
   - <b>为什么</b>：一段以 `<b>为什么…</b>` 开头的解释。
   概念在这一步里以 `### 概念 N：名称` 出现（见下）。
6. `## 本节小结`：`记住这些` 要点清单（5–8 条），然后是 `<b>留给下一节</b>：…` 钩子（全课最后一节可省略）。章末最后一节在这里加 `### 本章项目地图`。
7. `## 本节练习`：**3–5 题**，每题后紧跟「答案与解析」块
8. `## 概念索引`：每个概念一行，用本文件锚点：`1. [数值导数](#概念-1-数值导数)`
9. 导航行：`上一节：[…](…) · 返回大纲：[…](…) · 本章速查：[…](…) · 下一节：[…](…)`（首/末节省略对应项；末节可加「本章测试」）

除了上面这些，节里不再有别的 `##`。需要分段时在步骤里用 `###`。

### 6.1 概念：H2 还是 H3

| 写法 | 什么时候用 | 规则 |
|---|---|---|
| `### 概念 N：名称`（推荐） | 新库 | 写在第一次需要它的那一步里；短条目：一句话、准确定义（`Note` 标注块）、一个例子、一条易错点。不要求固定小标题 |
| `## 概念 N：名称`（过渡） | 老库逐节迁移时 | 必须夹在两步之间（前一个和后一个 `##` 都是「第 N 步」），不能连排，不能放在第一步之前或最后一步之后 |

- 全库只用一种写法，校验器发现混用会报 [R3]。
- 编号 N 从 1 起、本节内连续，`##` 与 `###` 都要带编号：门户的概念徽章按 `slugify("概念 N：名称")` 跳转，没有编号就跳不过去。
- 不是每个术语都要成为概念条目。脱离那一步就没意义的东西（某个参数、某行代码的作用）留在「为什么」里讲。

### 6.2 章末两件事

每章最后一节必须有：

- **章末通跑**：一个标题含「章末通跑」（或「冒烟」）的步骤，例如 `## 第 4 步：章末通跑：用尺子量 backward`。里面是一个【运行】，一条命令从头跑完整个 `project/`，带绑定的真实输出。非代码科目是「从头验算一遍推导本」「把句子本从头朗读并默写一遍」，带 `<b>你应该看到</b>`。
- **本章项目地图**：`### 本章项目地图`，一个 ```` ```text ```` 文件树（含 `project/`），每个文件一句话职责，以及 `<b>本章动了</b>：…` 哪些文件（新建 / 修改）。非代码科目写读者那份东西的目录（列表、表格或文本块都行，例如推导本每一页写了什么），加 `<b>本章动了</b>：…`，不要求 `project/`。

下面的文件树是代码类课程的样子：

```text
project/
├── check.py              草稿纸（Sec_1 新建，Sec_2 修改）
├── minigrad/
│   ├── __init__.py       包入口（Sec_1 新建，Sec_2 修改）
│   └── value.py          会 backward 的标量（Sec_2 新建）
└── tests/
    └── test_value.py     用数值导数核对 backward（Sec_2 新建）
```

练习格式：

- 题号写成 `**1.**`；选择题在 md 里写出 A/B/C/D 选项。
- 同一组题写进 `notes_data.js` 的 `sections[].quiz`，题干**逐字一致**（含行内代码），答案一致。

## 七、本章速查（`CX 速查.md`）

- 一页纸，读者复习和做测试前翻的那张"小抄"。模板见 `templates/cheat-sheet.md`。
- 只收本章已经讲过的内容：核心定义一句话版、公式、API/命令表、易错点、"什么时候用哪个"的对照表。**不写新知识，不写长解释**。
- 每条后面链到正文对应的小节锚点，方便回查。
- 篇幅建议 80–200 行。最终章（毕业设计）不需要速查。
- 在 `notes_data.js` 的章条目里登记 `sheet: { file: "/Cha_X 章名/CX 速查.md" }`，门户侧栏会出现「本章速查」。

---

## 八、章末测试（`CX 测试.md`）

- **满分恰为 100 分**，分值写在题号后：`**1.（5 分）**`。
- **客观题（选择/判断/填空）合计 ≥ 60 分**，门户会自动判分。
- 难度梯度：基础 ≈ 60 分，应用 ≈ 30 分，综合/拔高 ≈ 10 分。覆盖本章**各节**，不得只考一节。
- **从第 3 章起**含 10–20 分跨章回顾题，题号后标 `【回顾 CX】`：`**12.（5 分）** 【回顾 C1】 ……`。回顾题考的是前面章节里本章会用到的知识（间隔复习，见 `teaching-design.md`）。
- 答案区给每题的解析；计算题与主观题给评分要点与分值分配，门户靠它让用户自评。
- 同一份题目写进 `notes_data.js` 的 `chapters[].test.questions`（含 `score` 与 `analysis`），`total: 100`。
- 模板见 `templates/chapter-test.md`。

---

## 九、案例

复杂问题必须配完整案例：

- 有输入有输出（代码类：读者照【新建】/【修改】敲出来的完整代码 + 绑定的真实输出）；
- 有问题有结局（工程类：遇到的坑 → 怎么定位 → 最终方案）；
- 数据自洽（算例的每个中间量都能对上）。

不要用"例如某个函数……"一笔带过。

## 十、毕业设计（最终章）

全部内容完成后，生成最终章 `Cha_N 毕业设计/`，模板见 `templates/capstone.md`：

- 3–5 个选题，分层（巩固型 / 综合型 / 挑战型）。
- 每个选题：目标、要求、用到的章节（带链接）、完成标准、评分要点、示例或参考实现。
- 代码类科目从最后一章的 `project/` 出发给完整代码，并在注释里写明每段用到的是哪一节的知识，例如 `# 见 C3 Sec_2 自动微分：链式法则`。不要写 `C3-02` 这类旧编号。
- 最终章不需要速查；`notes_data.js` 里该章 `test: null`。
